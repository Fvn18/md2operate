# 0. 前提、范围与现状基线

## 0.1 已确认的三项前提

本规格书的写法由下列三项决策决定。它们不是推定，是产品方在评审后给出的明确答复；
若不成立，受影响章节整体作废（每项后已标出）。

| 编号 | 决策 | 取值 | 若推翻，作废的章节 |
|:--|:--|:--|:--|
| **D-1** | 目标读者 | **客户方业务与技术决策者**（非内部工程实施） | 全文改写体裁：承诺前置、实现下沉到附录 |
| **D-2** | 多租户 | **要，但先小规模**：单集群、租户数量在两位数以内起步，隔离从第一天就是硬要求 | §7 数据治理、§6 威胁模型优先级下降 |
| **D-3** | 输出是否允许变化 | **基本不允许**。同一输入必须得到同一版面；**唯一例外是引擎替换**，且须走显式授权并附版面差异报告 | §2 不变量、§4 缓存契约全部降级为「尽力」 |

**D-2 的直接影响**：多租户一旦成立，评审意见 REV-16 从 P2 **升为 P0**——因为现状的分隔面
（浏览器关闭沙箱、Markdown 允许原始 HTML、渲染页与 API 同源）在单人本地是合理取舍，
在租户之间是不可接受的。§6 按 P0 写。

**D-3 的直接影响**：本项目最硬的一条资产是「预览与导出同构、增量与全量逐字节相同」。
多引擎是它与生俱来的威胁（同一文档换引擎必然换版面），所以引擎替换不能是"降级矩阵里的
一个自动分支"，而必须是一次**有记录、可追溯、需授权**的动作（§5）。

## 0.2 范围外（明确不做）

- 不做通用文档转换网关：只服务 Markdown → 出版级 PDF / 高清位图这条主线。
- 不做在线富文本编辑器：输入是 Markdown 源码，客户自带编辑器或用自己的仓库。
- 不做协同编辑（CRDT）。评审意见 REV-20 指出，若将来要做，**编译输入的确定性**是前置条件；
  本版本把它列为范围外，只保留该前置条件为约束。
- 不做内容审核与事实核查：渲染服务不理解内容语义。

## 0.4 术语表与禁用词

| 术语 | 定义（唯一） |
|:--|:--|
| **task** | 一次 API 请求，可能产生多条产物路线 |
| **render** | 一次「输入指纹 → 产物」的渲染执行 |
| **artifact** | 单个产物文件（PDF / PNG / TEX / DOCX），有独立指纹 |
| **job** | 队列中的可调度单元，一个 job 可以零次、一次或多次 render（全命中即零次） |
| **slot** | 一个并发渲染槽位，约等于一个有效 vCPU 加一份内存配额 |
| **P0 / P1 / P2** | 只与**延迟目标**和**调度池**绑定，不与文档类型绑定 |
| **Key** | 缓存键，定义为完整输入指纹，含引擎、字体、平台、路由版本 |
| **executed_engine** | 实际使用的引擎；发生降级时不等于 requested_engine |
| **陈旧产物** | Key 相同但输入已变，或输入相同但产物与当前引擎不符 |

**禁用词**：本文档不列举禁用词，因为列举本身就会让这些词出现在正文里。
禁用词表由 `scripts/verify-docs.mjs` 维护，并在 CI 中对 `docs/enterprise-spec/` 全目录扫描。
判据只有一条：**这句话能不能被反例推翻**。不能推翻的形容词一律不写。

# 1. 服务承诺

## 1.1 可用性

| 项 | 承诺 | 如何度量 | 谁负责 |
|:--|:--|:--|:--|
| 服务可用性 | 99.9%（月度） | 合成探测每 30 秒一次，判定「不可用」的规则见下 | SRE |
| 「不可用」的定义 | 以下任一条持续 2 分钟：提交端点 5xx 比例 > 5%；产物下载端点 5xx 比例 > 5%；队列写入失败 | 服务端指标 | SRE |

**说明（对应 REV-26）**：这里不写「多活部署」，写**多可用区部署**——并把跨区数据面的约束
单列（§9）。安全承诺同样只写**已识别的利用链清单**（§6），不写覆盖全部未知攻击面的绝对化表述。

> 评审意见 CL-02 的裁定是「当前不可证伪」，因为原文没有定义「不可用」。上表把定义写死。

## 1.2 延迟

延迟承诺必须先钉死**执行位置**，再谈数值——这是评审意见 REV-03 的结论。

| 通道 | 执行位置 | 承诺（p95） | 度量方法 |
|:--|:--|--:|:--|
| **P0 交互预览** | `L0` 浏览器端（现状能力） | 输入事件 → 下一帧呈现，见下 | 浏览器内性能条目，逐键采样 ≥ 30 次 |
| P1 常规导出 | `L1` 同可用区服务端 | 提交 → 产物可下载 | 服务端计时，含排队 |
| P2 批量归档 | `L2` 跨节点分布式 | 按批承诺，不按单文档 | 批完成时间 |

**现状实测**（`scripts/bench.mjs`，10 万字符文档，1400×900 视口）：
逐键 p50 **24.4 ms**、p95 **25.6 ms**。这条路径**完全在浏览器端完成**：
Markdown 解析、公式排版、分块增量都在 Web Worker 内，主线程只负责把变化的块贴进 DOM。

因此：**把公式渲染搬到服务端的热缓存，在这条链路上是净增一次网络往返与一次调度**，
方向与目标相反。P0 通道固定为 `L0`。

#### REQ-SRE-001　P0 交互预览延迟
- 需求：P0 通道的交互预览在浏览器端完成，不经过网络往返。
- 依据：评审 REV-03 / 实测 p95 25.6 ms
- 验收：`scripts/bench.mjs` 报告逐键 p95 < 33 ms（两帧），且网络面板无渲染相关请求。
- 度量：逐键 p50 / p95。
- 关联不变量：INV-2
- 状态：已实现

## 1.3 吞吐

**不写「每秒 N 个任务」**。`task` / `job` / `document` / `page` 这四个词在本项目内部必须区分
（见 §0.4）。吞吐一律以**参考负载**加**单位产能**表达，这样任何人都能反推出需要的机器与费用。

### 参考负载

| 编号 | 画像 | 源文件 | 产物 |
|:--|:--|:--|:--|
| `W1` | 短文 | ≤ 5 KB | A4 单页 PDF |
| `W2` | 技术论文 | 约 100 KB，含公式、表格、代码块 | 20 页 PDF |
| `W3` | 长图 | 约 400 KB | 300 DPI PNG，≥ 2 MB |
| `W4` | 印刷件 | 约 50 KB | 1200 DPI 单页 PNG |

### 产能表达

产能写成 `docs/s/vCPU`（每秒每 vCPU 能完成的文档数），持续（≥ 30 分钟）与突发（≤ 60 秒）
分开报告：

| 负载 | 单文档耗时（现状实测） | 单机产能上限 |
|:--|--:|--:|
| `W1` | 约 2.2 s | 计算得出 |
| `W2` | 约 3.4 s | 计算得出 |
| `W3` | 约 3.5 s | 计算得出 |
| `W4` | 约 3.6 s | 计算得出 |

**产能算式的形式**（具体数字由阶段 0 的基准 harness 填入，见 §10）：

$$
\text{vCPU 需求} = \frac{\text{目标 docs/s}}{\text{docs/s/vCPU}} \times (1 + \text{冗余系数})
$$

#### REQ-SRE-002　吞吐以参考负载与单位产能表达
- 需求：任何吞吐承诺必须写成「参考负载 × docs/s/vCPU」，持续与突发分开。
- 依据：评审 REV-02
- 验收：文档中不出现无单位的吞吐数字；读者能据表格算出所需 vCPU 与费用。
- 度量：基准脚本可复现同一数字。
- 状态：待实现（阶段 0 交付基准 harness）

## 1.4 正确性与新鲜度

**对一个渲染服务，最危险的故障不是宕机，是「内容变了却返回旧产物」。**
宕机会被 99.9% 抓到；陈旧产物不会。所以正确性必须有独立的承诺行。

| 承诺 | 定义 | 度量 |
|:--|:--|:--|
| **陈旧产物率 = 0** | 输入指纹变化后，任何返回的产物必须对应新指纹 | 对账任务：随机抽样重算输入指纹，与产物指纹比对 |
| **静默降级率 = 0** | 任何降级（引擎替换、分辨率下调、栅格器回退）必须出现在产物清单与响应头 | 扫描产物清单中的降级字段 |

#### REQ-CACHE-001　陈旧产物率为零
- 需求：输入指纹变化后不得返回旧产物；输入中包含所有会影响产物的字段。
- 依据：评审 REV-08 / REV-11；本项目曾发生「漏 11 个输出相关选项进签名」的事故
- 验收：对账任务连续 7 天陈旧产物率为 0；漂移测试（§4）在 CI 中通过。
- 关联不变量：INV-3
- 状态：部分实现（客户端签名已覆盖 33 字段；服务端对账任务待建）

#### REQ-CACHE-002　降级必须可见
- 需求：任何降级都写入产物清单并在响应头以结构化字段返回。
- 依据：评审 REV-12
- 验收：构造一次降级请求，产物清单中 `requested_engine ≠ executed_engine`，且响应头含
  `X-MDP-Downgrades`。
- 关联不变量：INV-4
- 状态：部分实现（响应头已有路线字段；降级数组待补）

# 2. 不变量

不变量与「需求」的区别：需求可以延期，不变量一旦破坏就必须停止发布。
每一条都有一条可执行断言与一个 CI 门禁。

| 编号 | 不变量 | 断言 | 门禁 |
|:--|:--|:--|:--|
| **INV-1** | 预览与导出同构 | 预览逐块拼接与导出整篇 HTML 逐字节相同；允许差异白名单仅限页边距与分页相关 | `verify` |
| **INV-2** | 增量等于全量 | 增量渲染结果与全量渲染结果逐字节相同 | `verify:preview` |
| **INV-3** | 命中等于未命中 | 缓存命中的产物与未命中的产物逐字节相同 | 待建 |
| **INV-4** | 降级可见 | 任何降级出现在产物清单与响应头 | 待建 |
| **INV-5** | 取消不留残留 | 取消后无孤儿进程、无遗留临时目录 | `verify:cancel` |
| **INV-6** | 预检与执行一致 | 预检判定可渲染的路线，实际必须能渲染出产物（校验文件头） | `verify:kernel` 第 4 组 |

> **INV-6 的由来**：本项目曾出现「预检返回 409 不可用、而实际渲染完全正常」的缺陷，
> 根因是预检读了一个不存在的字段。这条路线的可用性判断必须与实际执行走同一份数据。

# 3. 调度与背压

## 3.1 分级调度

P0 / P1 / P2 只与延迟目标和调度池绑定，不与文档类型绑定（见 §0.4 术语表）。

**不写「按优先级抢占队列」**：抢占是操作系统术语，意味着中断正在运行的任务。
本服务的语义是**分级调度，不抢占运行中的任务**。

## 3.2 背压

背压不能靠「全局利用率超过 85% 就返回 429」——那样会把 P0 通道一起打掉。规则如下：

| 信号 | 阈值 | 动作 |
|:--|:--|:--|
| P0 池槽位占用率 | > 90% | 拒绝新的 P2，P0/P1 不受影响 |
| 队列等待时间（P1） | > 30 s | 拒绝新的 P2，`Retry-After` 带抖动 |
| 引擎池饱和度 | > 95% | 拒绝 P1 与 P2 |

**P0 走预留容量**：P0 使用独立池并保有最小容量，429 只作用于 P1 与 P2。

#### REQ-SCHED-001　P0 预留容量
- 需求：P0 通道使用独立调度池并保有最小容量，背压不作用于 P0。
- 依据：评审 REV-09
- 验收：在 P1/P2 满负荷压测下，P0 的 p95 不劣化超过 10%。
- 状态：待实现

#### REQ-SCHED-002　429 响应体可机器消费
- 需求：429 响应体包含 `retry_at`、`queue_class`、`quota_scope` 三个字段。
- 依据：评审 REV-09
- 验收：契约测试断言三个字段存在且类型正确。
- 状态：待实现

## 3.3 队列

任务队列的持久化语义必须写明，因为它决定重复执行是否安全：

- 队列持久化 ⇒ **至少一次**投递 ⇒ 渲染任务必须**幂等**。
  与缓存契约天然协同：同一 Key 的渲染可以安全重复执行，结果相同。

#### REQ-SCHED-003　渲染任务幂等
- 需求：同一 Key 的渲染任务可安全重复执行，产出一致。
- 依据：评审 REV-10
- 验收：对同一任务重复投递 3 次，产物指纹相同且只产生一份计费。
- 关联不变量：INV-3
- 状态：待实现

# 4. 缓存契约

## 4.1 核心不变量

**同一 Key ⇒ 同一字节。** 这条不变量唯一可能被破坏的来源是「有影响产物的输入没进 Key」。
因此 Key 的字段集合不能由人维护，必须**由构造渲染命令的同一处代码生成**。

## 4.2 Key 字段全表

| 字段 | 来源 | 变更影响 |
|:--|:--|:--|
| 源文档指纹 | 输入内容 | 全部产物 |
| 主题与样式 | 主题定义 | 版面与配色 |
| 字体**文件内容哈希** | 字体文件 | 字形与度量 |
| 引擎与版本 | 引擎二进制版本 | 版面 |
| `executed_engine` | 实际执行的引擎 | 版面 |
| 路由版本 | 路由器版本号 | 路线选择 |
| 日期与时区 | 渲染时刻 | 日期文本、时间戳元数据 |
| 语言与连字符规则 | 语言设置 | 断行 |
| 平台标识 | 运行平台 | 字体回退与栅格器选择 |
| 全部输出相关选项 | 命令行参数 | 对应产物 |

#### REQ-CACHE-003　Key 字段来自单一事实来源
- 需求：Key 的输入集合由构造渲染命令的同一处代码生成，新增输出相关选项时强制同步。
- 依据：评审 REV-11；本项目曾因漏 11 个输出相关选项导致陈旧产物
- 验收：漂移测试枚举全部输出相关选项，任一选项存在但未进 Key 即失败。
- 关联不变量：INV-3
- 状态：部分实现（签名已覆盖 33 字段；漂移测试待建）

## 4.3 一致性等级

| 等级 | 承诺 | 适用 |
|:--|:--|:--|
| 强一致 | 同 Key 的产物在同一时刻全局相同 | 同一平台内 |
| 平台一致 | 同 Key 的产物在同一平台内相同；跨平台命中率分开统计 | 跨平台 |

**必须回答的问题**：同一文档在两台不同节点命中同一 Key 时，产物是否允许不一样？
**答案：不允许**——平台维度进 Key，所以跨平台本就不是同一个 Key。

#### REQ-CACHE-004　块级内容寻址复用
- 需求：对语义分块计算内容指纹，未变化的分块不触发重新渲染。
- 依据：评审 CL-12
- 验收：同一文档二次编译，渲染器调用次数 ≤ 变化块数 + 1。
- 度量：二次编译耗时 ÷ 首次编译耗时。
- 关联不变量：INV-2
- 状态：已实现（浏览器端，复用率 99.7%）；服务端待建

# 5. 降级与取消

## 5.1 引擎替换规则

这是 **D-3** 的直接落地。同一输入必须得到同一版面，因此引擎替换不是自动降级，
而是一次需要授权的动作：

| 情形 | 是否允许自动发生 | 要求 |
|:--|:--|:--|
| 栅格器回退（如高分工具不可用） | 允许 | 分辨率与质量损失写入响应头 |
| 同一引擎内的重试 | 允许 | 记录次数 |
| **换成另一个排版引擎** | **不允许自动发生** | 需显式授权，附版面差异报告，`executed_engine` 进 Key |

#### REQ-COMPAT-001　引擎替换需授权并留痕
- 需求：排版引擎的替换不得自动发生；发生时必须记录 `requested_engine`、
  `executed_engine` 与差异报告。
- 依据：评审 REV-12 / D-3
- 验收：构造一次引擎替换，产物清单与响应头都能区分且可追溯；未授权时请求被拒绝而不是被降级。
- 关联不变量：INV-1 / INV-4
- 状态：待实现

## 5.2 路由器

#### REQ-COMPAT-002　路由决策可复现
- 需求：路线选择是 `(文档特征, 主题, 预设, 路由版本)` 的纯函数，输出写入产物清单并进 Key。
- 依据：评审 REV-13
- 验收：同一输入在任一节点的任一时刻得到同一路线；路由器版本变更视为破坏性变更。
- 状态：待实现

## 5.3 取消

取消的粒度在共享池里会波及他人，必须显式定义：

| 粒度 | 延迟 | 隔离性 | 后果 |
|:--|--:|:--|:--|
| 上下文级 | 低 | 好 | 资源回收较慢 |
| 进程级（现状） | 158 ms 实测 | **会丢弃同实例的其他上下文** | 需要池的重建 |
| 任务级协作式 | 高 | 最好 | 实现最贵 |

**现状**：结构为进程级——截图与打印一旦发出就无法撤销，终止浏览器实例是唯一能在半路停下的办法。

#### REQ-SCHED-004　取消的爆炸半径
- 需求：取消一个租户的任务不得影响其他租户正在运行的任务。
- 依据：评审 REV-15 / D-2
- 验收：一个测试证明取消 A 的任务后，B 的任务产物仍正确且未被中断。
- 关联不变量：INV-5
- 状态：待实现（现状会在池重建期间影响同实例任务）

# 6. 安全

多租户成立（D-2）之后，本节按 P0 写。

## 6.1 两条渲染路径的威胁模型

原文把隔离全部押在 TeX 路上，而实际在「最前台」的是浏览器路线。本节把两者对称处理。

| 攻击面 | 现状 | 目标 |
|:--|:--|:--|
| 浏览器沙箱 | 关闭 | 启用命名空间隔离 + 只读根文件系统 + 无网络 + seccomp |
| Markdown 原始 HTML | 允许 | **多租户下默认关闭**，或经消毒后放行 |
| 渲染页与 API 同源 | 是 | **必须不同源**：独立端口或独立域名，不携带凭据，CSP 禁止外联 |
| 出站网络 | 允许 | 默认拒绝，含 `file:`、浏览器内部协议、内网段、云元数据地址 |
| 资源耗尽 | 无配额 | CPU、内存、墙钟、进程数、输出字节五项配额 |
| 服务鉴权 | 默认无令牌、仅回环 | 强制鉴权，禁止回环以外的未鉴权访问 |

#### REQ-SEC-001　渲染页与 API 不同源
- 需求：渲染页面必须从与 API 不同的源加载，且不携带任何凭据。
- 依据：评审 REV-16 / D-2
- 验收：注入用例——文档中嵌入脚本尝试调用 API，请求被拒绝。
- 状态：待实现

#### REQ-SEC-002　出站默认拒绝
- 需求：渲染环境出站流量默认拒绝，只允许白名单地址。
- 依据：评审 REV-16
- 验收：用例覆盖私网段、云元数据地址、文件协议、浏览器内部协议，全部被拒。
- 状态：待实现

#### REQ-SEC-003　资源配额
- 需求：CPU、内存、墙钟、进程数、输出字节五项配额独立生效，越界时终止并如实报告。
- 依据：评审 REV-16
- 验收：用例包含递归宏、深嵌套结构、超大图片、压缩炸弹四类，全部被配额终止而非拖垮服务。
- 状态：待实现

## 6.2 TeX 路径的旋钮清单

原文的「完全禁用 shell-escape」不够精确。可执行的旋钮如下：

| 旋钮 | 取值 | 作用 |
|:--|:--|:--|
| `shell_escape` | `f`，并在调用侧显式关闭 | 禁用一切对外执行变体 |
| `openin_any` / `openout_any` | `p`（paranoid） | 禁绝对路径与上级目录穿越 |
| TeX 宏包树 | 只挂载受控白名单目录 | 替代「宏包白名单」的不可执行定义 |
| 可写目录 | 指向隔离目录 | TeX 必须写辅助文件（`.aux` / `.log` / `.out`），这是物理必需 |
| 转换器参数面 | 集中构造，用户不可注入任意命令行参数 | 现状已如此，作为不变量写明 |

#### REQ-SEC-004　TeX 旋钮白名单
- 需求：上述五个旋钮按表取值，且转换器的参数面由服务端集中构造。
- 依据：评审 REV-17
- 验收：一组恶意文档用例，全部被拒或无副作用。
- 状态：部分实现（参数面集中构造已达成）

# 7. 数据治理与保密

## 7.1 现状的一个真实泄露面

引擎的输出会被中继进任务日志（`server/render.mjs` 的错误尾捕获），
**正文片段与文件路径可能因此落进日志与事件流**。

#### REQ-ASSET-001　日志默认不落正文

- 依据：评审 REV-05；现状确有泄露面
- 验收：跑一份含标记字符串的文档，在全部日志与事件流中检索该标记，零命中。
- 状态：待实现

## 7.2 加密、保留与删除

| 项 | 要求 |
|:--|:--|
| 静态加密 | 正文与产物落盘即加密 |

# 9. 成本与容量

## 9.1 单价表（形式）

| 项 | 计价单位 | 说明 |
|:--|:--|:--|
| 计算 | 元 / vCPU·小时 | 渲染槽位 |
| 内存 | 元 / GB·小时 | 位图解码是主要消耗 |
| 出口流量 | 元 / GB | 长图产物为主要消耗 |
| 存储 | 元 / GB·月 | 产物与缓存副本 |

## 9.2 容量水位

#### REQ-SRE-003　内存上界可计算
- 需求：峰值内存用公式表达，超阈场景用**分块渲染**策略而不是「溢出到临时文件系统」。
- 公式：

$$
M_{\text{peak}} \approx \sum_i \left( W_i \times H_i \times 4 \right) + M_{\text{encode}} + M_{\text{engine}}
$$

- 依据：评审 REV-04 / CL-20。实测：300 DPI 长图 2953×16719 解码后约 197 MB；
  1200 DPI 单页 8325×2013 约 67 MB；同内容按 1200 DPI 长图约 3.16 GB。
- 验收：给出每条路线的用量估算与实测峰值。
- 状态：待实现

## 9.3 磁盘接触（重述）

**不写「零磁盘接触」**——TeX 路线物理上必须写辅助文件，且高分辨率位图的解码缓冲远超任何
小缓冲阈值。改为三条可测性质：

| 编号 | 性质 | 验收 |
|:--|:--|:--|
| `P-a` | 不落**持久**盘：中间产物只存在于内存或临时文件系统 | 渲染期间监控持久盘写入 |
| `P-b` | 临时文件系统用量计入内存限额 | 压力测试不 OOM |
| `P-c` | 峰值内存有上界公式（见 §9.2） | 实测与公式偏差在给定范围内 |

#### REQ-SRE-004　磁盘接触可测
- 需求：按 `P-a` / `P-b` / `P-c` 三条性质验收，并按路线给出对照表。
- 依据：评审 REV-04
- 验收：给出每条路线的临时文件系统用量估算与实测峰值。
- 状态：待实现

# 12. 待验证假设与替代路径

## AH-1　格式转储

**假设**：预编译格式转储可以降低排版引擎的冷启动开销。

**状态：未验证，且在本项目的组合下实测失败。**

实测证据原文：

```text
xelatex: fatal: Could not undump 627825 8-byte item(s) from fmt1.fmt.
```

两种调用形式都失败：文档首行的魔数形式与命令行选项形式。
注意两者同时出现会冲突，复测时只取其一。

**替代路径**（不依赖该假设，按风险从低到高）：

1. **已完成的固定开销治理**：本项目实测，每次调用曾无条件启动一次 `pandoc --version`
   （31.2 ms），连「源文件未变直接跳过」那次也付。改为惰性解析后，渲染路径只启动一次
   转换器、缓存命中路径不再启动。这类改动**不改变输出**，风险最低。
2. **宏包减重**：测量导言区逐项成本，先压掉「每包必付」的固定部分。
3. **引擎路线**：仅在 **D-3 授权**下评估，必须附版面差异报告。

#### REQ-COMPAT-004　AH-1 必须先结案
- 需求：在目标平台复测格式转储；失败则启用替代路径 1 与 2；启用替代路径 3 需要 D-3 授权。
- 依据：评审 REV-01；实测失败记录见上
- 验收：文档中不出现任何「已达到某耗时」的断言；实验卡含环境矩阵、步骤、成功判据与失败替代。
- 状态：替代路径 1 已实现
