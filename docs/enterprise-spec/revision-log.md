## P0：会误导实施

### REV-01　`.fmt` 内存转储降级为待验证假设

- **原文主张**：SLO 表、§3.1、阶段二交付三处把 TeX 预编译内存转储写成既成能力，称可把 PDF 从 1.5 s 压到 0.4 s。
- **改法**：不再出现在任何承诺位置。§12 立为 `AH-1`，附**实测失败原文**（`xelatex: fatal: Could not undump`）与"魔数形式与命令行选项形式不可同时使用"的复测注意；给出三条替代路径，其中路径 1（固定开销治理）已实现且**不改变输出**；路径 3（换引擎）挂到 D-3 授权之下。
- **证据**：本机实测；评审 REV-01。
- **验收**：`spec.md` 中无"已达到某耗时"的断言；`AH-1` 卡片含环境矩阵、步骤、成功判据、失败替代。✅

### REV-02　吞吐改为「参考负载 × 单位产能」

- **原文主张**：`≥500 tasks/s`。
- **改法**：§1.3 定义参考负载 `W1`–`W4`，产能一律写 `docs/s/vCPU`，持续与突发分开；给出产能算式；把具体数字留给阶段 0 的基准 harness（`S0-2`）。
- **证据**：评审 REV-02 的反推（PDF 口径需 1,650–3,000 槽位）。
- **验收**：文档中无无单位吞吐数字；读者能据此算出 vCPU 与费用。✅

### REV-03　先钉死 P0 执行位置，再定延迟

- **原文主张**：预览 p95 ≤ 50 ms，机制为「AST 增量解析 + 分布式公式热缓存」。
- **改法**：§1.2 把 P0 通道固定为 **浏览器端**（`L0`），并把"把公式渲染搬到服务端热缓存是净增一次往返"这一判断写进正文；术语改为**块级增量 + 身份继承**（与实现一致）；延迟承诺带测量方法。原文的"分布式公式热缓存"不再出现在 P0 机制列。
- **证据**：实测逐键 p50 24.4 ms / p95 25.6 ms（浏览器端完成）。
- **验收**：P95 定义含测量方法与执行位置；机制列无跨机缓存。✅

### REV-04　「零磁盘接触」重述为三条可测性质

- **原文主张**：零磁盘管道 + 64 MB 缓冲阈值 + 溢出到临时文件系统。
- **改法**：§9.3 改为 `P-a`（不落持久盘）/ `P-b`（临时文件系统用量计入内存限额）/ `P-c`（峰值内存上界公式）；§9.2 给出内存公式与三组实测数字（300 DPI 长图约 197 MB、1200 DPI 单页约 67 MB、1200 DPI 长图约 3.16 GB）；超阈场景规定用**分块渲染**而不是溢出。
- **证据**：评审 REV-04 / CL-20；TeX 必须写辅助文件是物理事实。
- **验收**："零磁盘"字样被替换为 `P-a`/`P-b`/`P-c`，并给出各路线用量估算。✅

### REV-05　新增数据治理与保密

- **原文主张**：全文缺失。
- **改法**：新增 §7 整章：加密（静态与传输）、日志脱敏、保留期与删除、审计、数据驻留；并把**现状的真实泄露面**（引擎输出被中继进任务日志）写成 `REQ-ASSET-001`。
- **证据**：`server/render.mjs` 的错误尾捕获会把输出中继进日志与事件流。
- **验收**：能回答"客户要求删除某文档的全部产物，多久、如何证明"。✅（`REQ-ASSET-002`）
